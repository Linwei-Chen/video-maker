# 视频方法论：什么是好，什么是坏

> 用法：**开工前**读 §一，让全片对着七条判据做；**自查时**拿 §二 的病历逐条对号入座；**出故障时**查 §三。§二 每一条都是"表面上看没问题、观众体验却很差"的陷阱，格式统一为【病症 → 病理 → 处方】。

## 一、好视频的七条判据

| # | 判据 | 自查问题 |
|---|---|---|
| 1 | **一条主线** | 随机抽掉一幕，全片讲理应受伤——若毫无影响，那一幕不该存在。讲透一件事胜过提到十件事 |
| 2 | **每帧是插画** | 任意时刻暂停截图，单独看经得起端详吗？（对照判据：这能当一张海报吗？） |
| 3 | **视觉有身份** | 颜色即角色——同一对象全片同色，观众不读标签也知道是谁；核心道具可被口头复述（"那个发光的钟"） |
| 4 | **节奏有呼吸** | 重要动作后有停顿，蓄力后有爆发，紧张后有舒展；剪辑密度服从叙事分区而不是均匀撒 |
| 5 | **数字诚实** | 每个数可溯源，不确定就明说"目前的最佳估计是"，绝不夸大 |
| 6 | **音画互证** | 旁白讲到机制时画面正在演示它；时长由配音驱动——永远不出现"画面演完了、人还在念"或反向的冻帧 |
| 7 | **收尾有余味** | 不说"感谢观看"；最后一句要么回收开头意象，要么打开一个更大的问题 |

快速判断法：一个陌生人看 30 秒——他若问"这到底在讲什么"，是主线病；他若不问但也停下了，是节奏或质感病。

## 二、坏视频病历本

### A · 内容病（最致命的一类）

**A1 成果展示片** → 通篇是"这东西多厉害"，只有结论没有因果链；解说满是"赋能、革新、颠覆"式口号。
病理：观众要看的是"为什么"，不是"是什么"；口号句信息量为零。
处方：结构固定为「现象 → 为什么 → 怎么变 → 证据 → 与我何干」；每句话写完自问"它推进理解了吗？"推进不了就删。前 5 秒必须出现真信息或真问题。

**A2 模板感** → 每一幕同一套版式（标题渐显 + 色块 + 字幕），机械重复到可预测。
病理：版式重复等于信息量为零，"可预测"直接转化为无聊。
处方：每幕开工前查「概念→母题速查表」（cutting-edge.md §D），让视觉语言贴合学科本质；不同幕用不同构图骨架。

**A3 技巧堆砌** → 满屏辉光粒子特效，但没有一个镜头服务于论点。
病理：技法是句子，不是文章；无目的动画就是噪音。
处方：每个动画动作必须能回答"它在强调什么？"——答不上来就删。

**A4 空洞类比** → 比喻只图好听、不管映射是否成立；且从不说明类比的失效边界。
病理：错误的类比比没有类比更糟——它会给观众植入新的误区。
处方：类比选定后标注 source/target 映射关系与失效边界，越界处明说"这个比喻到这里就不成立了"。

### B · 视觉病

**B1 PPT 帧** → 纯色底 + 大标题 + 扁平色块 + 字幕条。
病理：这是幻灯片不是动画；整片没有一帧"动"的表达。
处方：分层构图三件套——星云渐变背景（`fs.nebula_bg`）+ 渐变/辉光主体（`fs.grad_rect`/`glow_line`/`trail`）+ 前景芯片标注（`fs.chip`）。

**B2 空洞帧与空卡片** → t>2s 画面仍大面积空黑；卡片只有边框、内容迟迟不填。
病理：观众看到的是"还没准备好"的画面；空框停留超过 2 秒等同事故。
处方：t≤2s 主体必须在位；卡片进场即填充内容；每幕第 0 帧满帧可见（渐变入场可以，全黑不行——底板缓动渐入会让场景交界出现全黑首帧）。

**B3 中文渲染错误** → 缺字形显示豆腐块（PingFang 无 ⇒⇔✓✗⟩⁻ 等字形）；公式里夹中文；半角问号混进中文标题。
处方：缺字形一律用 →、=、×、√、CJK 括号或 mathtext 替代；公式内禁中文；标题用全角标点。

**B4 字幕描边吞笔画** → 给 30 号中文字幕加深色描边。字笔画本来只有 3~4px 宽，描边两侧各吃掉 1.5px，"叠/毁/终"这类笔画密的字直接残缺，看上去像重影或锯齿。
处方：纯白无描边 + 底部半透明黑底条。宁可加底条，不要加描边。

**B5 低对比与图文打架** → 灰字贴灰底看不清；文字压在曲线/图形上互相损毁。
处方：白字 + 黑底垫；标注与图形错位摆放；写完用抽帧目检对比度。

**B6 图文错位** → 字幕在讲 A，画面在演 B。
病理：观众被迫在两条信息线间做选择，两头都没接住。
处方：分镜表逐幕列「画面元素 vs 旁白要点」两列对照，剪辑完成后逐句核对。

### C · 声音病

**C1 机械感配音** → 系统自带合成音（如 macOS say 类）念旁白，一听出戏。
处方：神经网络语音打底（edge-tts 云健）；换声只重建音轨后 `-c:v copy` 替换，画面零重渲。

**C2 断流废片** → 在线 TTS 偶发断流，产出 0.5 秒左右的截断音频，混进成片就是瘆人的静音跳变。
处方：合成后校验"时长 ≥ 字数 × 0.10s"，不达标判废同语速重试；连续失败熔断回退本地合成并如实标注降级。

**C3 术语误读** → "1.8×"读成"一点八克"、缩写读成怪词、生僻人名瞎念。
处方：配音前建 PRON 读法表逐条改写（缩写逐字母、数字+单位展开、×→乘、生僻词注音）。

**C4 旁白尾巴冻帧** → 先定画面后排声音，结果配音比画面长，片尾画面冻住十几秒干念。
病理：音画时长的系统性错配。
处方：**配音驱动时长**——先合成再逐幕核对「语音时长 vs 场景时长」，超长就精简文案或拉长场景；所有淡出相对场景时长写，禁止写死绝对时刻。

### D · 工程病

**D1 apad 无限填充写满磁盘** → 混音忘了限长参数，wav 无限增长直到撑爆磁盘，整个过程没有任何报错。
处方：混音一律 `amix=inputs=2:normalize=0:duration=first`，明令禁用 apad。

**D2 渲染超时全线报废** → 单条命令渲整片，超出 shell 时间限额被杀，前面全白渲。
处方：逐场景渲染 + concat；单条命令 ≤8 分钟；同一时间只跑一个渲染进程。

**D3 环境地狱** → 在转译（Rosetta）或老旧 Python 环境里跑重型动画库，卡死在低分辨率试渲染，零产出。
处方：matplotlib 路线用原生 arm64 + 固定 venv 即可安稳；Manim 类必须原生环境 + 源码编译依赖（pycairo 等无轮子时禁用多余后端最小化编译），旧环境直接禁用，不要侥幸。

**D4 修复殃及池鱼** → 为改一个场景重渲全片、重配音轨，把已完成的好工作置于风险中。
处方：外科手术式修复——只重渲受影响场景 → concat → `-c:v copy` 换混流，旁白轨不动；修复后必复检抽帧留证。

**D5 慢速截图管线** → 用浏览器自动化逐帧截 PNG，实测只有 ~8 帧/秒。
处方：Chrome CDP 直连截 JPEG（快一倍以上）；headless 加 `--no-proxy-server` 防系统代理劫持 localhost。

### E · 流程病（最隐蔽的一类）

**E1 流程全绿但成片平庸** → 调研、审稿、质检每项都"通过"，观众却觉得无聊。这是所有陷阱里最危险的一个：**给执行者一套合格判据，它就会去优化"合格"，而不是"优秀"——防缺陷的清单永远防不住平庸。**
处方：质量门槛必须包含超越"没错"的判据——美感门三问（这帧当插画及格吗？遮住字幕画面还在讲故事吗？放进头部频道里丢人吗？）；黄金镜头先行：先把最能代表全片的一镜做到自己真心满意，再以其质感为下限铺开全片。

**E2 自检盲区** → 作者盯自己的片子一百遍，问题是熟视无睹的。
处方：独立视觉验收——派一个只看抽帧、不读代码文档的独立 Agent，判乱码/遮挡/空洞/构图 + 美感三问；抽帧密度每幕 ≥1 帧，加首/中/尾。

**E3 并发写冲突** → 多个子任务直写同一个 manifest/索引文件，互相覆盖。
处方：共享汇总文件由主控统一写；子任务只写自己的专属目录。

**E4 编造细节** → 拿不准的数字抱着"反正差不多"的心态写进去。
病理：科普内容的全部资本是可信；一个错数字足以让观众否定全片。
处方：拿不准宁可不写；每个入片数字进事实表并标出处，由审稿门复核。

## 三、检修模式（出问题时怎么办）

1. **画面局部问题** → 只重渲该场景 → concat → `-c:v copy` 混流 → 复检抽帧
2. **配音问题** → 重建音轨 → 响度对齐 → `-c:v copy` 替换音轨（画面不动）
3. **时长对不上** → `probe_duration` 对账；场景时长之和 vs 成片时长，差 ±1s 内视为合格，超出查 concat 参数
4. **兜底纪律** → 无论遇到什么困难，必须交付可正常播放的成片（可降级为核心场景版，如实标注 status=degraded 并记录原因）；交白卷是唯一不可接受的结局
